本文回答三件事：现在什么能用、凭什么、还缺什么。产品应该是什么见 [PRODUCT.md](PRODUCT.md) 与 [ARCHITECTURE.md](ARCHITECTURE.md)，正在做什么见 [TASKS.md](TASKS.md)。本文只记状态，不复述契约。

## 读法

- **状态**
  - `已验收`：独立 Tester 按真实用户路径验收通过。
  - `待复验`：验收过，但之后的改动动到了它，还没有重新独立验收；自动化测试可能仍然通过。
  - `契约`：契约已写明，但没有独立验收记录（可能未实现、部分实现，或只有自动化测试）。
- **<覆盖列名>**：`✓` 最近一次独立验收覆盖了它；`○` 只有自动化测试；`–` 不适用或还没有实现。
- **最近独立验收**：`#<里程碑> @<提交>（日期）`，提交是该里程碑的 `Verified-Commit`。验收用了受控夹具（模拟的外部服务、合成输入等）时标「受控」。
- **已知缺口**：一句话结论；细节留在提交正文与 `.tmp/evidence/milestone-<ID>/`。
- **维护**：Brain 增删条目并立即独立提交（不在工作区留未提交草稿）；Router 在里程碑结案前重读本文件，只同步该里程碑 `Features` 所列条目对应的行（含状态、覆盖列、最近独立验收与受控标记、已知缺口、下方「回归测试」表链接，以及发布里程碑的「发布与版本」状态）。条目按「用户会说我能做某件事」来切，契约细节留在契约文档。
