# 工程与验证纪律 Skill

## 核心原则（设计推导见 [references/rationale.md](references/rationale.md)）

1. **契约规定目标，源码与运行结果说明当前事实**：两者不一致时定位根因，不通过篡改契约或放宽测试把缺陷伪装成正确。
2. **共同可观测，不维护隐式状态**：判断、修改和验证证据必须对人直接可见，不在不透明缓存或临时脚本里藏匿状态。
3. **找根因，不打表层补丁**：连续两次在同一问题或同一失效机制上打局部补丁仍未解决，说明根因或隐含模型未建立，必须停下来重新推演。

## 工具选择梯度（操作选最轻，验收选最真）

严格区分「日常执行/自动化操作」与「用户体验验收」两个方向相反的场景：

```text
L1 结构化接口：服务自身的 API / SDK / 原生结构化工具
L2 确定性 CLI：git、curl、构建工具、测试运行器、编译器等命令行
L3 脚本化驱动：浏览器 DOM/网络自动化脚本、客户端驱动协议
L4 用户感官表面：真实窗口点按交互 + 视觉截图肉眼审视（Human-Like UI Inspection）
```

1. **日常操作、构建与逻辑自检（`L1 → L2 → L3`）**：优先选最轻、最确定的一级，有 L1/L2 不动用慢速 GUI 点击。
2. **产品与用户体验验收（直达交付层）**：不拿底层 `L1/L2` 脚本或 DOM 断言绿灯替代顶层 `L4` 真实体验验收。交付物包含 GUI、网页或客户端界面时，独立验收（Tester）必须在真实渲染界面上像普通用户一样操作并截图肉眼审视排版、对齐、遮挡、截断与文案。
3. **实测再断言**：宣称“环境不具备某能力”前必须先实测，区分“未配置”与“宿主不支持”，不静默跳过验证。

## 子 Agent 派发纪律（摘要）

完整角色协议与并发配额以 `multi-agent-collab` Skill 为唯一权威事实源，日常执行守住三条硬边界：

1. **Fast Path（`0` 子 Agent）vs Slow Path（派 Worker，按需派 Tester）**：$\le 5$ 步工具调用的局部微调或上游契约冻结由主会话直办；完整业务模块实现或跨多文件重构下沉至隔离的 Worker；只有改变外部可观测表面（GUI、CLI、API 行为）时才派独立 Tester，纯内部重构靠 Worker 门禁证据与 Auditor 兜底，不派 Tester。
2. **写操作单工作区并发上限 = `1`**：同一共享工作树同一时刻最多 `1` 个活跃写 Agent；仅当满足 ① 独立 Git Worktree、② 写文件集 100% 物理正交、③ 共享 Schema 已冻结时，才允许按垂直模块并行写（上限 $\le 3$）。
3. **只读操作并发上限 = `2 ~ 4`**：按正交子系统或独立审查维度扇出，不按零碎单文件拆出大批子 Agent。

## 变更与防御式编码纪律（13 条铁律）

1. **精确覆盖范围**：说清哪些情况变了、哪些相邻情况没变，不同性质的错误不混作同一种兜底。
2. **到达所有同类位置（Reach Every Sibling）**：修一处缺陷后全局检索同构模式（同类调用点、子命令、守卫），在同一变更内一并修复。
3. **重推导下游依赖**：改了公式、数据结构、布局或时序，必须找出所有假设旧语义的调用方、缓存和测试并重新验证。
4. **读失败即未知（Fail-closed）**：读取、解析或校验失败时，结果是“未知”而非“空/无/相等”；安全与权限守卫遇到读取失败必须拒绝放行。
5. **预览零副作用**：`dry-run`、`plan`、`preview` 等只读操作不写入任何持久或临时状态。
6. **错误分类窄化**：一个错误码或异常标记只对应它精确描述的那一种失败，不吞掉未知异常。
7. **外部系统取值溯源**：对接外部系统或协议时，字段类型与取值从官方契约或二进制实测获取，不凭字段名臆测。
8. **时序不承载异步就绪猜测（No Readiness-by-Sleep）**：异步就绪与状态同步必须来自显式的事件、回调、Promise、调用顺序或状态机（协议规范或硬件时序明确要求的退避/采样延时除外），拒绝用 `setTimeout(..., 0)`、让出一次事件循环或固定延时碰运气等渲染/数据就绪。
9. **锁内禁无界阻塞与并发状态隔离**：持有互斥锁时不发起无界网络/磁盘 I/O 或可能死锁的阻塞调用；共享可变状态在移交并发读取前完成初始化，警惕含嵌套引用的浅拷贝；新增后台任务、定时器或并发共享状态的变更必须跑通语言/平台的竞态检测（如 `go test -race`、TSan 或并发压测）。
10. **可选输入显式声明双分支（No Fallback Chains）**：拒绝用一长串 `?.` 与 `??` 默认值掩盖契约缺失；可选参数必须在接口契约中同时规定“存在时”与“缺省时”的确定性行为。
11. **单值单语义（One Value States One Fact）**：“尚未查询（`unknown`）”“查询结果为空（`empty`）”与“具体值（`value`）”是三种不同事实，用可辨识联合类型或显式枚举区分，不用单一 `null / undefined` 混代。
12. **直接重构原函数，不套娃包装、不截胡**：修改既有函数或组件行为时，直接修改原函数定义并删净旧逻辑；不保留原函数再用同名重赋值包一层（如 `fnBase = fn; fn = ...`），不拦截事件屏蔽未删旧监听器，不先渲染到错位再挪动节点。
13. **Git 兜底历史，不留备份垃圾，严护未提交现场**：已提交源码和 `.gitignore` 专用测试沙盒直接原地修改，不留 `_old / _backup` 废弃副本，不写备份拷贝或进程扫描脚本；修改或清理前必查 `git status`，**严禁擅自覆盖、回滚或删除工作区中他人或先前会话留下的未提交修改（Uncommitted / Untracked Work）与未跟踪本地夹具**。

## 代码注释、文档去噪与 Commit Body 审计账本

1. **只写契约，不写心路历程**：注释、JSDoc 和长期文档只陈述类型签名表达不出的契约（前置/后置条件、不变量、所有权、锁序、反直觉失败行为），并指名函数符号而非易过期的行号；不写调试推理过程或复盘流水账。
2. **已落地文档一律用现在时**：合入后只描述系统当前如何工作，不留 `should`、迁移待办清单或 `"（已实现！）"` 等易腐状态词。
3. **内部重构零文档税**：文档只链接源码文件与符号名，不抄录常变细节；对外职责、状态流转和失败契约未变时，内部重构无需改文档。
4. **Commit Body 作永久验证账本**：
   - **Subject**：点明模块前缀，平实陈述用户或调用方现在可观测的行为变化，拒绝空洞的 `fix bug` / `update code`。
   - **Body**（实质性功能、修复或重构按需轻量记录）：① **意图或根因**（设计边界，或 Bug 触发根因、修复机制及同步覆盖的 Siblings）；② **验证证据**（实际运行的测试命令与结果；涉及核心逻辑或修 Bug 时说明如何手动破壁 `Broken by hand` 确认测试精准报红）；③ **未覆盖边界**（`Not tried`，如有）。

## Git 主干线性收口、分支清理与公开仓卫生

1. **草稿态与主干账本分离（线性原子主干）**：
   - `main` 只接收经过验收的线性原子提交，严禁 `wip:` 半成品提交与无意义的菱形 `merge commit` 落入 `main`；
   - $\le 5$ 步 Fast Path 微调与上游契约冻结可直接单次干净提交到 `main`；完整功能、里程碑或多轮返工必须在本地短命分支或隔离工作树中开发，验证通过后按「最小可独立回滚语义单元」（单切片 = 1 条；多正交切片 = 每切片 1 条）**Squash 线性合入 `main`**，将完整意图与验证证据写入该条 Commit Body，并立即删除本地分支与工作树（多 Agent 切片协同细则见 `multi-agent-collab` Skill）；
   - **严禁改写或强推已落入 `main` 的历史**：需要撤回已合入变更时，显式新增 `revert` 提交，绝不对 `main` 执行 `reset --hard` 强推或 `rebase` 改写。
2. **远端零僵尸分支与跨人 PR 协议**：
   - 本地探索、草稿或单机多 Agent 切片分支**不推送远端**，避免远端残留无人清理的僵尸分支；
   - 跨人协作或开源仓库 PR 统一使用短命分支：分支落后 `origin/main` 时执行 `git fetch && git rebase origin/main` 后用 `git push --force-with-lease` 更新（禁止裸 `--force`；高并发仓库优先走 Merge Queue），合入采用 `Squash & Merge` 并开启合入后自动删除远端分支；
   - **重放优于硬解腐烂冲突**：分支落后过久或与新冻结契约发生大面积硬冲突时，直接放弃旧分支，基于最新 `main` 按契约重放意图与守卫测试，不在陈旧冲突文本上硬补。
3. **公开仓库隐私卫生**：
   - 向公开仓库提交前检查提交身份，优先使用平台隐私邮箱（如 GitHub `<id>+<username>@users.noreply.github.com`）而非个人真实邮箱；
   - 若发现既有公开历史已含个人邮箱，优先切换后续提交配置，未经用户明确确认严禁擅自改写已推送的历史。

## 双速调试回路、UI 自拍与实验台先行（Harness-First）

1. **双速调试回路**：
   - **内环（Worker 高频自测，目标 `< 1~3s`）**：核心算法、布局计算、路由与状态流转在零 GUI 启动开销的纯函数或内存无头测试中闭环，不每改一行就打包重型客户端或跑慢速 E2E。
   - **UI 交卷自拍看镜子（Worker 交卷前必做）**：凡涉及前端、客户端、图表或样式排版修改，单测跑绿后、交卷前，Worker 必须对真实渲染界面截 1~3 张关键状态图存入 `.tmp/evidence/milestone-<N>/`，亲自用图像查看工具检查并当场修掉重叠、截断、错位或穿帮。
   - **外环（Tester 真实用户终验，每里程碑终点 1 次）**：Tester 在真实环境中独立盲测、首轮一次性列全缺陷，将通过验收的截图保留在 `.tmp/evidence/milestone-<N>/` 供人最终审美把关。
2. **实验台先行（Harness-First）**：编写复杂业务、GUI 或引擎功能前，先打通三条感官管道，不处于致盲状态盲猜补丁：
   - **异常与状态直出文本**：未处理异常、渲染错误与关键状态迁移结构化输出到 stdout/日志，不静默吞错或仅弹图形框；
   - **CLI 状态自省入口**：提供命令行/测试可触发的状态导出（如 `--dev-dump-state` 或无头仿真入口）；
   - **一键冒烟脚本**：将“构建 → 沙盒启动 → 触发动作 → 收集日志/截图 → 清理退出”封装为单条确定性命令。
3. **三面独立互证**：排查问题时独立校验三面——**行动面**（正式公开入口，不在生产代码开后门）、**观察面**（只读日志/进程/数据库查询，观察不制造状态）、**判定面**（对照业务契约检查终态，退出码 0 / HTTP 200 不单独作为成功证据）。

**根因定位公式**（保留失败现场，写出可证伪结论再改代码）：
> 当 `<触发条件>` 发生时，`<责任模块>` 因为 `<错误机制>` 未能完成 `<应尽职责>`，导致用户观测到 `<表面症状>`。

## 验证分层、反 AI Slop 单测四铁律与测试隔离

下层通过不能替代上层验收：

```text
静态检查（Typecheck / Lint） → 单元测试 & 架构守卫单测（Guard Tests） → 集成测试（真实依赖/持久化） → E2E 验收（正式入口 + 真实数据流）
```

- **架构规则优先写成守卫单测**：模块依赖方向、禁用写法（如 `fnBase = fn` 重赋值套娃、抠源码假测试）、配置与 Schema 同步等可机械校验红线，直接写成 `tests/` 下的守卫单测随套件执行，不只写在 Markdown 里。
- **反 AI Slop 单测四铁律**：
  1. **手动破壁验证（Broken by Hand, Each Red）**：新增或修改的核心行为测试，必须手动破坏其保护的关键业务分支（反转条件、注释状态更新、丢弃关键字段），确认测试精准报红（`FAIL`），再恢复变绿；改坏代码仍 `PASS` 的恒真测试立即删除或重写。
  2. **边界替身优先，拒绝内部 Mock**：禁止 `readFile("src/...")` 抠源码跑正则或 `eval / vm.runInContext` 假单测，禁止普通业务测试把内部协作模块全 Mock 掉。调用真实模块导出入口跑通内部流转，仅在进程外边界（第三方 HTTP、时钟、文件系统）或显式声明的底层故障注入点使用受控替身。
  3. **真实故障字节优先 + 表驱动边界覆盖**：协议兼容与线上故障回归优先保存真实原始字节流夹具；新协议/算法用紧凑表驱动/性质测试覆盖缺失字段、空值、截断块与极值，不在强类型语言中为编译器已拦截的非法类型堆冗余单测。
  4. **全仓测试门禁（Full-Suite Gate）**：交卷前必须运行全量测试套件与静态检查（不只跑改动所在的包）；主干既有红灯必须修复或立项，不以“main 上原本就红”为由带病合入。
- **职责分离**：代码单测、破壁验证、全仓门禁与 UI 自检由 Worker 完成，Worker 不给自己下最终验收结论；Tester 不写代码或单测，只模拟真实用户验收（完整契约见 `multi-agent-collab` Skill）。
- **测试沙盒、硬超时与防吞错**：单测在临时目录/沙盒 HOME 运行，不碰宿主机真实配置或发起真实公网请求；`.gitignore` 专用沙盒（如 `.tmp/`）直接读写复用，不写快照备份或进程扫描。链式管道命令必须开启 `set -o pipefail`。测试运行器与长耗时验证脚本必须配置显式硬超时（单用例/单文件级），严禁在测试进程内嵌套调用争夺同一构建或包管理目录锁的子命令，防止单次挂起或自死锁拖死整条自动化验证链。

## 架构加减法与 AI-Native 选型剃刀

引入框架、外部库、分包或设计抽象前，遵循五条极简准则：

1. **第一性原理三问**：
   - **质疑妥协性**：该方案是物理性能和最终体验最优，还是昔日为迁就人类手写速度而引入的拐杖？
   - **探寻原生解**：不考虑手写劳累，底层系统、数学几何或关系代数上最直接的原生解法是什么？**100~200 行内能写完的功能直接写零依赖代码，不为此引入外部库**。
   - **追求形式化确定性**：优先编译期最严格、状态最显式的技术栈（显式坐标优于隐式盒模型盲猜，强类型编译器优于动态弱类型）。
2. **垂直高内聚小包 + 单向无环 DAG**：按业务领域或物理机制垂直分包，拒绝 `service / handler / repository / util / helpers / common / managers` 水平大泥球和垃圾桶包；包间保持由外层向纯逻辑内核的单向无环依赖（具体层级由项目 `ARCHITECTURE.md` 定义），用守卫单测锁死，禁止反向与循环依赖。
3. **保留 DI 模式，砍掉 DI 容器**：通过构造函数显式传参注入依赖，禁止引入 `wire / fx / Spring IoC / TSyringe` 等自动注入容器；在程序入口（`main`）显式手动组装依赖，构造函数参数超过 5~6 个即拆分子系统。
4. **可仿真纯内核、变化率隔离与跨端对齐**：
   - 全力借力真物理/数学底座（数据库、原生 UI、渲染物理引擎），但把 80%+ 核心规则与状态机剥离为零重型引擎/零外部 I/O 依赖的纯文本逻辑内核（Simulatable Core），配内存级仿真替身实现毫秒级单测；二进制资产仅作最薄视觉壳；
   - 高确定性 Core 与高频突变的外部适配 Edge 物理拆包或经插件宿主隔离；低频控制面走纯文本/JSON，高频热路径留同内存空间或 C-ABI 零拷贝；
   - 多端 UI 共享 `PRODUCT.md`、设计 Token 与同步对账表，需 bit-for-bit 一致的算法内核通过编译二进制库共享。
5. **内部删除优于兼容**：单一场景直接实现，第二个真实用例出现再抽象；内部重构直接删除旧路径与废弃代码，不堆内部兼容层（对外公开协议除外）。

## 停止与升级规则（人机边界）

遇到以下任一情况，立即停止自主修改并交由人裁定：
1. **改变对外承诺**：缩减功能范围、修改公开 API 契约、变更持久化数据格式或降低性能/安全指标；
2. **不可逆生产/外部操作风险**：删除生产真实用户数据、触发真实账单、执行无回滚线上部署，或覆盖不受 Git 追踪的外部原始材料（已提交 Git 源码及 `.gitignore` 测试沙盒可直接原地修改）；
3. **外部高危输入**：审查外部 PR 时触碰 CI 配置、构建脚本、新增未知外联网络、读写凭证或引入混淆二进制；
4. **局部补丁死循环**：对同一问题连续两次修复均告失败，或发现既有架构根本冲突；
5. **价值判断权衡**：需在用户体验、安全边界与研发成本之间做业务取舍。

## 验收清单

- [ ] 修改范围最小化，未顺手改动无关代码或静默篡改契约
- [ ] 同类缺陷位置（Siblings）已全局排查并同步修复
- [ ] 新增/修改测试已执行手动破壁验证（`Broken by hand, each red`），未使用内部 Mock 或抠源码假测试
- [ ] 已运行全仓测试套件（而非仅局部改动包），明确区分真实环境验证与边界替身验证
- [ ] 若改变了文档化的架构契约或接口，已在同一变更中同步更新对应文档
- [ ] 实质性提交已在 Commit Body 中简明记录意图/根因与验证证据（核心逻辑或修 Bug 含 `Broken by hand` 证明）
- [ ] `main` 仅落入经过验收的线性原子提交（无 `wip:` 半成品与菱形 `merge commit`），未改写已合入 `main` 历史，本地/远端短命分支已清理，公开仓库提交身份使用隐私邮箱
- [ ] 未运行或受环境限制无法覆盖的验证项已显式列出，无隐瞒或伪装完成
