# 跨模型异源协作与交叉审计参考实现（Cross-Model Peer & Auditor）

本文件是 [SKILL.md](../SKILL.md) 中**跨模型异源协作**与 `Auditor` 角色的通用落地参考，适用于单宿主原生编排与跨窗口双环两种拓扑。**本文件不硬编码任何具体模型型号、代理商或私有通道**，模型与推理深度由项目 Brain / 主控按当前环境与任务风险决定。

## 一、为什么异源模型不应只当“事后审计员”？

- **独立冷会话**解决的是“作者自我确认偏见”（上下文去污染）；
- **异源模型家族**进一步解决“同源盲区共振”（同一模型家族在隐含假设、调试思路、测试边界和 Fail-open 习惯上高度相关）。
- 如果只把异源旗舰模型关在研发链路末尾当“审 diff 质检员”，会浪费前 80% 最高杠杆的认知多样性——方案已经锚定、错误假设已经写成代码、测试盲区已经同源固化。因此异源模型应定位为**全周期第二大脑与双向协作者（Cross-Model Peer）**，默认高推理深度按需介入。

## 二、全周期六大高杠杆协作模式与一条物理边界

| 模式 | 默认权限 | 触发时机与核心作用 | 为什么划算 |
| :--- | :--- | :--- | :--- |
| **1. 方案独立构思与互搏（`debate`）** | `read-only` | **0→1 构思或关键架构/产品取舍前（先于主力定稿）**：让主会话与异源模型各自从第一性原理独立出方案，主控提炼分歧交人裁定 | 打破单模型先入为主的锚定效应，避免事后只能小修小补 |
| **2. 疑难根因排错（`debug`）** | `read-only` | **连续两次修复失败，或复杂并发/协议/跨系统诡异故障**：附失败日志与关键源码请异源模型冷上下文诊断并给最小鉴别实验 | 零历史假设包袱，瞬间击穿同源调试隧道视野 |
| **3. 对抗边界测试设计（`adversarial-tests`）** | `read-only` | **写关键测试前 / 加固高危状态机与契约**：只看契约与接口签名，独立设计边界、竞态与故障注入矩阵 | 打断“同源写实现又写测试”的相关盲区 |
| **4. 第一性全局架构体检（`first-principles`）** | `read-only` | **低频周期体检 / 重大重构前**：跳出 diff 通读核心契约与源码，专门拷问妥协层、隐式状态副本、DAG 破口与 10× 尺度瓶颈 | 防止“每块砖都干净但整栋楼越来越臃肿”的局部最优陷阱 |
| **5. 既有方案红队（`plan`）与合并前实证审计（`diff`）** | `read-only` | **方案定稿前**与**合并/发版/跳过 Tester 后**：0 噪音抓真实 Bug、假测试、反模式与契约漂移 | 高信噪比兜底，不拖慢日常编码节奏 |
| **6. 隔离 Worktree 专项攻坚（`implement`，可选）** | **显式授权 `workspace-write`** | **硬核纯逻辑内核/算法/并发攻坚**：在独立隔离 Git Worktree + 短命分支中实现并自测，再由主控（主力模型）反向逐行审查、复跑全仓门禁并 Squash 线性合入 `main` | 真正实现**双向异源互审**，而非单向“A 写 B 审” |

**物理工具边界红线**：不要把日常 GUI / Web 体验验收（`Tester`）强行下放给没有原生浏览器驱动的无头 CLI，否则会丧失截图交互闭环、拉长反馈周期。GUI 验收留在具备原生浏览器能力的主宿主内，异源 CLI 专攻高推理密度的构思、排错、测试设计、架构反思、代码审计与隔离内核攻坚。

## 三、零硬编码的模型配置优先级

宿主侧封装调用脚本时，模型与推理深度必须遵守以下优先级，严禁把某个具体模型 ID 或私有网关名写死在代码或协议里：

```text
1. Brain / 主控在本次调用显式传入的参数（如 --model / --effort）
2. 环境变量覆盖（如 AUDIT_MODEL / AUDIT_EFFORT）
3. 宿主外部 CLI 自身的默认配置（不传模型参数，直接沿用用户本机配好的主力旗舰模型）
```

## 四、两套核心 Prompt 门槛（日常实证审计 vs. 第一性构思与体检）

### A. 合并前局部实证审计（`diff` / `plan`）——追求 0 噪音高精准

```text
你是一名独立、冷启动的外部代码与架构审计官（Auditor），当前运行在只读沙盒中。
你正在对另一模型家族产出的工作做异源交叉验证。

硬性实证门槛（严格遵守）：
1. 只报告以下四类有明确依据的问题，禁止提出没有实证的主观风格建议：
   - [BUG] 真实逻辑错误、状态机漏分支、并发竞态、边界条件或 Fail-open 漏洞（给出 文件:行号 与触发路径）；
   - [WEAK-TEST] 假测试或“改坏核心逻辑仍可能通过”的测试缺口（给出测试 文件:行号 与逃逸分支）；
   - [ANTI-PATTERN] 违反项目明文红线的反模式（给出 文件:行号）；
   - [CONTRACT] 违背项目契约文档（AGENTS.md / ARCHITECTURE.md / PRODUCT.md / LESSONS.md）具体条目的实现或文档漂移。
2. 所有结论必须基于实际读取的文件或提供的 git diff 证据，不猜测未读过的文件。
3. 若完整 diff 已内联提供，优先直接分析，仅在核对行号或上下文时批量只读读取相关文件。
4. 若未发现任何满足上述门槛的实证问题，只输出一行：NO_ISSUES。
5. 若发现问题，按严重程度输出紧凑清单（每条含：[P0/P1/P2] [类别] 文件:行号 — 一句话结论、证据与触发路径、建议修法），末尾附 SUMMARY: P0=x, P1=y, P2=z。
```

### B. 第一性架构体检 / 方案互搏 / 疑难排错（`first-principles` / `debate` / `debug`）——跳出 diff 但同样反空话

- **第一性体检（`first-principles`）**：解除 `diff` 与 1~3 轮限制，通读核心契约与关键模块源码，围绕五问拆骨（① 哪些抽象/兼容层/依赖是旧惯性妥协、② 是否存在多处隐式状态副本、③ 稳定内核与易腐边缘是否真物理隔离、④ 控制面能否 1 分钟排障重导、⑤ 10× 规模下哪层物理崩塌）；每条质疑必须落到具体模块/文件、被质疑的隐含假设、更简原生替代方案与真实代价，严禁空泛套话。
- **方案互搏（`debate`）**：先检验问题前提本身是否问歪，再独立给出 2~3 个本质不同的方向及决定胜负的核心假设与失效边界，拒绝顺着主力既有结构微调。
- **疑难排错（`debug`）**：抛弃既有猜测，按「触发条件 → 责任模块（`文件:行号`）→ 错误机制 → 表面症状」给出可证伪假说与最小鉴别命令，严禁建议延时 `sleep` 或表层补丁。

## 五、工程提速、活性监控与安全约束

1. **默认只读 + 写权限显式隔离门禁（Fail-Closed）**：默认强制只读沙盒与一次性无痕会话；仅在明确触发隔离攻坚模式（如显式 `--mode implement --worktree-write`）时才自动创建独立隔离 Git Worktree（置于已 `.gitignore` 的 `.tmp/worktrees/` 或独立临时目录）并授予 `workspace-write`，严禁触碰主工作树、`main` 或执行 `git push`；
2. **内联 diff / 上下文与大改动分治**：`diff` 模式下将 `<= 80KB` 的 unified diff 直接内联压低轮数；超大改动按正交模块拆成 2~3 次定向只读审查并行执行；`debug`/`debate` 支持内联有限大小的失败日志或契约文件；
3. **活性心跳 + 分态空闲超时（替代机械总超时）**：高推理深度模型在大型仓库下健康运行 15~30 分钟很常见，单一机械 10 分钟总超时既会误杀正常任务、又对真实故障反应迟钝。封装脚本应优先启用 CLI 的结构化事件流（如 `--json` JSONL）并采用四层活性监控：
   - **分态空闲超时（按推进事件清零）**：每次收到真实推进事件（工具调用起止、推理步完成）即重置计时；区分 **LLM 思考态**（随推理深度自适应，如 `high=360s`、`xhigh=600s`）、**本地命令执行态**（紧收如 `90~120s`）与 **收尾退出态**（如 `30s`）；
   - **Fail-Fast 致命错误与重试熔断**：命中 401 鉴权失败、配额耗尽、模型不可用或连续重试死循环立即终止，**严禁让 stderr 重试噪音重置空闲计时器**；
   - **活锁熔断 + 宽松总上限**：对连续重复同一命令（如 5 次）或命令总数超预算（如 80~120 次）立即熔断，并保留宽松总时长兜底（如 30~40 分钟）；
   - **实时心跳 + 全进程组级联清理**：静默期周期性输出带 OS 进程/网络连接状态的心跳（供人或上层看门狗区分「慢但在推进 → 续期」与「静默宕机 → 终止」）；捕获外层 `SIGTERM`/`SIGINT`，中止时按保存的 PGID 执行 `SIGTERM → SIGKILL`（不以组长退出提前结束，确保杀净忽略 `SIGTERM` 的后代）；
4. **隔离输出与 Fail-closed**：每轮使用独立临时输出文件（绝不复读上轮遗留 `--out` 文件），要求退出码为 0 且收到完整结束事件（如 `turn.completed`，清除中途旁白）才原子发布最终报告；任何异常均保留日志并显式报错，绝不把失败伪装成 `NO_ISSUES`。

## 六、主流外部 CLI 对接范式（按本机实际工具替换占位符）

以下为通用无硬编码的调用形态示例（均不写死模型名，由 Brain 按需附加参数或沿用本机 CLI 默认旗舰配置）：

```bash
# 示例 A：通过 Codex CLI（只读沙盒 + 无痕会话 + JSONL 活性流 + 隔离输出）
codex exec --sandbox read-only --ephemeral --json --color never \
  -C "<repo-root>" \
  -c 'approval_policy="never"' \
  -o "<per-run-temp-report>" - < "<prompt-file>"

# 示例 B：通过 Claude Code 非交互只读模式
claude -p --permission-mode plan < "<prompt-file>" > "<per-run-temp-report>"

# 示例 C：通过 Gemini CLI 非交互模式（只读工具集）
gemini -p "" < "<prompt-file>" > "<per-run-temp-report>"
```

若宿主原生支持多模型子代理或 Swarm，也可直接由主控派生异源模型子代理执行上述同一套协作模式，无需调用外部 CLI。

## 七、主控核实与双向互审闭环（绝不盲从）

1. **只读构思/排错/审计结果逐条核实**：`debate`/`first-principles` 提炼实质分歧交人裁决；`debug`/`adversarial-tests` 按最小实验复现并落地为破壁单测；`diff`/`plan` 逐条核对 `文件:行号`，区分真问题与误报；
2. **隔离写结果双向反向审查**：当异源模型在隔离 Worktree 完成专项攻坚后，由主控（主力模型）亲自逐行审查 diff、复跑全仓门禁与破壁验证，确认无误再按最小语义单元 Squash 线性合入 `main` 并立即删除该 Worktree 与短命分支；
3. **水位线推进**：若项目维护 `docs/LESSONS.md` 的 `reviewed-through` 水位线，全部经核实的审计实证清零后再推进至最新 `HEAD`。
