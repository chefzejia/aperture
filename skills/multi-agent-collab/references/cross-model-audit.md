# 异源跨模型交叉审计参考实现（Cross-Model Read-Only Auditor）

本文件是 [SKILL.md](../SKILL.md) 中 `Auditor` 角色在跨模型场景下的通用落地参考，适用于单宿主原生编排与跨窗口双环两种拓扑。**本文件不硬编码任何具体模型型号、代理商或私有通道**，模型与推理深度由项目 Brain / 主控按当前环境与任务风险决定。

## 一、为什么优先用异源旗舰模型做审计？

- **独立冷会话**解决的是“作者自我确认偏见”（上下文去污染）；
- **异源模型家族**进一步解决“同源盲区”（同一模型家族容易对同类边界漏项、假测试和隐含假设同时视而不见）。
- 审计属于**低频、高杠杆**动作，单次耗时略长完全可以接受，因此默认倾向选用**与当前主力执行模型异源的主流旗舰推理模型 + 高推理深度（如 `high`）**。

## 二、两个高杠杆触发节点与一条反模式红线

| 节点 | 做什么 | 为什么划算 |
| --- | --- | --- |
| **1. 架构 / 契约 / 复杂机制定稿前** | 红队反证（`plan` 模式）：把方案文档 + 关键源码交给异源模型，专找隐含假设、状态机漏分支、并发竞态、Fail-open 与契约冲突 | 写代码前 1 次审查省下后续数轮返工 |
| **2. 合并前 / 发版前 / 跳过 Tester 的内部重构后** | 逆熵审计（`diff` 模式）：审查提交区间或未提交改动，按实证门槛抓真实 Bug、假测试与契约背叛 | 低频介入，不拖慢日常编码节奏 |

**反模式红线**：不要把日常 GUI / Web 体验验收（`Tester`）强行下放给没有原生浏览器驱动的无头 CLI，否则会丧失截图交互闭环、拉长反馈周期。GUI 验收留在具备原生浏览器能力的主宿主内，异源模型专攻纯代码、契约与方案审计。

## 三、零硬编码的模型配置优先级

宿主侧封装审计命令或脚本时，模型与推理深度必须遵守以下优先级，严禁把某个具体模型 ID 或私有网关名写死在代码或协议里：

```text
1. Brain / 主控在本次调用显式传入的参数（如 --model / --effort）
2. 环境变量覆盖（如 AUDIT_MODEL / AUDIT_EFFORT）
3. 宿主外部 CLI 自身的默认配置（不传模型参数，直接沿用用户本机配好的主力旗舰模型）
```

## 四、通用实证门槛 Prompt 模板

向只读异源模型发送审计请求时，固定携带以下约束，防止输出主观风格噪音：

```text
你是一名独立、冷启动的外部代码与架构审计官（Auditor），当前运行在只读沙盒中。
你正在对另一模型家族产出的工作做异源交叉验证。

硬性实证门槛（严格遵守）：
1. 只报告以下四类有明确依据的问题，禁止提出没有实证的主观风格建议：
   - [BUG] 真实逻辑错误、状态机漏分支、并发竞态、边界条件或 Fail-open 漏洞（给出 文件:行号 与触发路径）；
   - [WEAK-TEST] 假测试或“改坏核心逻辑仍可能通过”的测试缺口（给出测试 文件:行号 与逃逸分支）；
   - [ANTI-PATTERN] 违反项目明文红线的反模式（给出 文件:行号）；
   - [CONTRACT] 违背项目契约文档（AGENTS.md / ARCHITECTURE.md / PRODUCT.md / LESSONS.md）具体条目的实现或文档漂移。
2. 所有结论必须基于实际读取的文件或提供的 git diff 证据，不猜测未读过的文件。
3. 若完整 diff 已内联提供，优先直接分析，仅在核对行号或上下文时批量只读读取相关文件。
4. 若未发现任何满足上述门槛的实证问题，只输出一行：NO_ISSUES。
5. 若发现问题，按严重程度输出紧凑清单（每条含：[P0/P1/P2] [类别] 文件:行号 — 一句话结论、证据与触发路径、建议修法），末尾附 SUMMARY: P0=x, P1=y, P2=z。
```

## 五、工程提速与安全约束

1. **强制只读 + 一次性无痕会话**：外部审计 CLI 必须以只读沙盒运行（禁止写入工作区）且不复用历史会话上下文；
2. **内联 diff 压低轮数**：端到端耗时约等于 `调用轮数 × 单轮 TTFT`。将 `<= 80KB` 的 `git diff <base>..HEAD` 直接内联到首轮 Prompt 中，避免外部 Agent 花 5~10 轮反复拉 diff，可把耗时压低数倍；
3. **非交互与 Fail-closed**：关闭交互审批提示防止无头卡死；若命令退出非零、超时或报告为空，保留末尾错误日志并显式报错，绝不把审计失败伪装成 `NO_ISSUES`。

## 六、主流只读 CLI 对接范式（按本机实际工具替换占位符）

以下为通用无硬编码的调用形态示例（均不写死模型名，由 Brain 按需附加模型参数或沿用本机 CLI 默认旗舰配置）：

```bash
# 示例 A：通过 Codex CLI（只读沙盒 + 无痕会话 + 最终报告落盘）
codex exec --sandbox read-only --ephemeral --color never \
  -C "<repo-root>" \
  -c 'approval_policy="never"' \
  -c 'model_reasoning_effort="high"' \
  -o "<report-file>" - < "<audit-prompt-file>"

# 示例 B：通过 Claude Code 非交互只读模式
claude -p --permission-mode plan < "<audit-prompt-file>" > "<report-file>"

# 示例 C：通过 Gemini CLI 非交互模式（只读工具集）
gemini -p "" < "<audit-prompt-file>" > "<report-file>"
```

若宿主原生支持多模型子代理或 Swarm（如单宿主同时提供多个异源模型家族），也可直接由主控派生一个只读异源模型子代理执行上述同一份 Prompt，无需调用外部 CLI。

## 七、主控核实闭环（绝不盲从审计报告）

1. **逐条核实**：Brain / 主控收到 Auditor 报告后，必须亲自读取对应 `文件:行号`（必要时运行单测或手动破壁验证），明确区分 **经核实的真问题** 与 **误报**；
2. **真问题派 Worker 修复**：在当前里程碑或清理提交中修复并补齐回归守卫测试；误报只需在汇报中简短说明排除依据，不盲目改代码；
3. **水位线推进**：若项目维护 `docs/LESSONS.md` 的 `reviewed-through` 水位线，全部实证问题清零后再推进至最新 `HEAD`。
