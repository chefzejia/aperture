# 多 Agent 协作 Skill

## 为什么拆角色与两种执行拓扑

角色拆分只看两种差异，不看能力差异：

- **信息差异**：作者的上下文里装着“我为什么这么写”，自己验收会退化为自我确认，所以 Worker 与 Tester 必须分开；长会话会产生顺从偏差和同源盲区，所以需要一次性冷会话（且优先异源模型）的 Auditor。
- **交互对象差异**：面对人类聊天的会话与由自动化唤醒的后台会话，阻塞语义完全不同。只有把思考环与执行环拆到两个独立窗口或不同宿主时，才需要显式立住无人值守的 Router，避免后台会话停下来向空气提问。

**同一套协作内核，按宿主能力二选一执行拓扑**（设计推导见 [references/rationale.md](references/rationale.md)）：

| 拓扑 | 适用宿主与场景 | 角色映射与调度方式 | 调度板与唤醒 |
| --- | --- | --- | --- |
| **拓扑 A：单宿主原生编排（默认首选）** | 具备原生子代理 / Swarm、隔离工作树与内置浏览器代理的现代单窗口宿主 | 主会话兼任 **Brain + Router**，直接用宿主原生能力派生隔离的 Worker、全新 Tester 与按需 Auditor（或调只读异源 CLI 跑审计） | **无需常驻外部 Router、无需 `post-commit` 钩子**；`docs/TASKS.md` 仅在跨会话长任务时按需建立，不当进程间消息总线 |
| **拓扑 B：跨窗口 / 无人值守双环** | Brain 与执行器分属不同窗口/宿主，或需要无人值守后台异步排空多里程碑队列 | 思考环（Brain，唯一面对人类）与执行环（常驻无人值守 Router 派生 Worker / Tester / Auditor）彻底分离 | 以 `docs/ROLES.md`、`docs/TASKS.md` 队列与 `.git/hooks/post-commit` 边沿唤醒串联两环，见 [references/git-bus.md](references/git-bus.md) |

## 角色

| 角色 | 所在环与交互对象 | 职责 | 模型倾向 | 不做什么 |
| --- | --- | --- | --- | --- |
| **Brain** | 思考环，唯一面对人类（拓扑 A 中兼任 Router） | 承接人类意图，做产品与架构决策、冻结上游公共契约、决定审计模型与推理深度；拓扑 B 下向 `docs/TASKS.md` 追加或标废里程碑并只提交目标文档；处理 `blocked` 与最终审美裁定 | 旗舰模型 | 不亲自写大块业务代码；拓扑 B 下不覆盖或删除仍为 `pending` 的里程碑，要改就标 `superseded` 再追加新的；不把冗长工具日志带进对话 |
| **Router** | 调度者（拓扑 A 由主会话兼任；拓扑 B 为执行环唯一常驻会话，由自动化唤醒、对面没有人） | 取单、**派生**切片 Worker 与里程碑 Tester、管理隔离 Worktree；Tester 打回时现场分诊、按机制记 `docs/LESSONS.md` 并直接拍板返工；结案、排空队列、按条件派生 Auditor 并核实其报告 | 次旗舰或由主会话兼任，决断力强 | 拓扑 B 下**不停下向人类提问、不等待回复、不短超时早退**、不把显性问题转给 Brain、取单不改状态/不提交；**不自己改切片代码，哪怕只有两行**，只派生不代做 |
| **Worker** | 执行面；从切片派出到所在里程碑结案，期间保留供返工，结案后关闭 | 开工前读 `docs/LESSONS.md`；在分配的本地短命分支或隔离 Worktree 内实现一个完整切片，交卷前跑通全仓门禁、破壁验证、写清 Commit Body 并做 UI 自检 | 次旗舰，编码执行力强 | 不把本地草稿分支推上远端，不向 `main` 落 `wip:` 或菱形 `merge commit`；不改上游冻结契约；不写内部 Mock 或脱离真实环境的假测试；不给自己下验收结论 |
| **Tester** | 验收面；每个里程碑派生一个全新会话，同一里程碑内的返工复验沿用，结案后关闭 | 按产品形态模拟真实用户验收整个里程碑（GUI 优先使用宿主原生浏览器/视觉能力），一轮穷尽缺陷，归档证据，核对授权边界，向主控/Router 出报告 | 工具与视觉能力强 | 不替 Worker 写代码或测试；不拿脚本绿灯当体验验收；不做快照备份、进程扫描等防御性内耗；不碰用户真实数据 |
| **Auditor** | 按需派生的一次性全新冷会话，不由钩子或外部进程拉起 | 在低频高杠杆节点审查：① 重大架构/复杂机制定稿前红队反证或周期第一性架构体检；② 合并前、发版前或满足睡前审计条件时审查提交区间；只报告有实证的问题 | **优先与主力异源的主流旗舰模型 + 高推理深度**（具体型号由 Brain 按环境与任务决定，不硬编码） | 不复用任何旧会话上下文；默认只读不修改源码；不提没有实证的主观风格建议 |

### 跨模型异源协作（不止于事后审计）

异源模型（与当前主力不同模型家族）的价值来自**认知分布与盲区去相关**，不应局限于代码写完后的只读审计。除 `Auditor` 之外，可在全周期按需以「异源第二大脑（Cross-Model Peer）」身份介入五个高杠杆节点（详见 [references/cross-model-audit.md](references/cross-model-audit.md)）：

1. **0→1 方案构思与互搏（定稿前）**：面对复杂产品或架构权衡，让主会话与异源模型**各自独立从第一性原理推演方案**，再提炼核心分歧与取舍交由人裁定，打破单模型先入为主的锚定效应；
2. **疑难排错破盲（连续两次修复失败时）**：主会话陷入同一错误心智模型打转时，把失败现场、日志与关键源码交给冷上下文异源模型独立做根因诊断与最小鉴别实验，打破调试隧道视野；
3. **独立对抗边界测试设计**：让异源模型仅基于契约与接口签名独立设计边界、并发与故障注入测试矩阵，打断“同源模型写实现又写测试”的盲区相关；
4. **合并前实证审计（`diff`）与低频第一性全局体检（`first-principles`）**：前者 0 噪音抓局部 Bug/假测试/契约漂移，后者跳出 diff 专门拷问妥协层、隐式状态副本与 10× 尺度瓶颈；
5. **双向互审与显式隔离写（可选）**：默认保持只读沙盒；对极硬核纯逻辑内核/算法/并发模块，经显式授权可允许异源模型在**独立隔离 Worktree** 中实现并自测，再由主控（主力模型）反向逐行审查、复跑全仓门禁并 Squash 线性合入 `main`。日常依赖视觉与交互的 GUI/Web 验收仍留在具备原生浏览器能力的主宿主内完成。

### 模型分层与动态路由（不硬编码版本）

1. **按角色梯队分工，不写死版本号**：`Brain` 用当前旗舰；执行面（`Worker` / 宿主执行层）用高性价比次旗舰编码档；纯只读代码库探索、大范围检索或常规网页交互降到轻快档省配额；`Auditor` 优先异源主流旗舰加高推理深度。
2. **算力分层交给宿主原生双模型，多代理只服务于隔离与并行**：
   - 若宿主原生支持可配置的 **Orchestrator + Executor 双模型编排**，单切片常规开发直接交给宿主原生双模型闭环，不必仅为“切换次旗舰模型”额外套壳拉起多 Agent 团队编排；
   - 仅在需要**冷上下文信息隔离**（独立 `Tester`、只读探索）或**多切片物理正交并行写**（独立工作树）时，才派生独立子代理或团队编排（1–2 个轻型隔离任务用宿主轻量子代理；≥3 个长时并行协作再启用团队看板）；
   - 若某宿主轻量子代理存在隐式降级到低配模型的已知缺陷，在宿主全局配置中显式指定高推理档或替代通道即可，不把特定宿主的绕路写进公开协议。
3. **偏好外置到宿主全局配置，业务仓库零绑定**：业务仓库（含 `AGENTS.md` 与 `docs/ROLES.md`）与公开 Skill 绝不写死具体模型型号、家族名或特定派发器/档位参数；个人模型路由与编排偏好集中写在宿主全局规则的一处文件里维护，换代时只改这一处，防止项目文档把调度器拉回旧路径。
4. **用户当次指定最高优先**：用户在当前对话显式指定的模型或编排方式，永远覆盖上述默认分层策略。

## 会话生命周期

状态在文件和 Git 里，不在会话里。拓扑 A 中只有人类面对的主会话常驻；拓扑 B 中只有 Router 是执行环唯一常驻的会话（它是队列的唯一消费者，由宿主排队避免两个 Router 并发排空同一个队列；同时协议不依赖宿主绝不丢信号，由排空循环兜底）。Worker、Tester、Auditor 在两种拓扑下都按需派生、用完即关。

- **Worker**：从切片派出到所在里程碑结案，期间保留供返工。新 Worker 接不住上一个里程碑的工作，说明控制面（代码、commit body、`ARCHITECTURE.md`、`LESSONS.md`）有缺口，补缺口，不靠留着会话。
- **Tester**：每个里程碑派生一个全新会话，保持“不懂实现的新用户”视角；同一里程碑内的返工复验沿用，它知道自己列过哪些问题。
- **反假死看门狗（活性驱动，非机械总超时）**：异步派发与后台命令都不允许无限静默干等，也不应仅靠过短的机械总超时误杀大型项目的健康长任务。主控派生 Worker / Tester 或执行长耗时后台任务时，使用带自动取消条件的一次性看门狗定时器（正常回报自动取消）；本地确定性测试与构建入口内置显式硬超时，而长耗时远程推理/外部审计改用**实时事件流心跳 + 分态空闲超时（每次推进事件重置）+ 活锁熔断 + 宽松总上限**。看门狗超时唤醒主控时，先检查状态与实时心跳：确认仍在持续推进则续期等待，仅在静默超阈值、进程僵死或活锁时终止清理。
- **提示缓存**：宿主若能命中是红利，协议不依赖它。

## 里程碑、切片与调度板

调度单位统一是**里程碑**：一条真实用户路径能端到端走通、Tester 一轮就能判定的可观测增量。每个里程碑内含若干**切片**（格式见下文“通信契约”）。拓扑 B 以 `docs/TASKS.md` 为两环唯一交接面；拓扑 A 仅在跨会话长任务时按需建 `docs/TASKS.md` 记录里程碑进度，单会话即可收官的任务无需强建文件队列。

- **切片**：Worker 的工作单位，各带写作用域 `Scope`。Scope 重叠或同切面紧密耦合的串行逻辑并成同一个切片；Scope 物理正交才分开并行，仅当存在跨目录的上下游接口先后依赖时标明`（依赖 S1）`并按序派发。只有一个切片的里程碑直接在区块里写 `Scope`，不单列切片。一个里程碑暂定 3~5 个切片封顶，按打回率调整。
- **里程碑的切点**：用户路径闭合；后续工作建立在尚未验证的体验决策上；不可逆或高风险操作之前。渲染、版式、并发等组合空间大的机制单独成切片或里程碑，并写明验收矩阵的维度，不与功能验收捆绑。
- **主干不改写、草稿可丢弃**：已落入 `main` 的切片提交默认不回滚、不改写也不强推（新里程碑在当前 HEAD 上继续，要回滚由新里程碑明写显式 revert）；尚未合入 `main` 的里程碑或切片草稿分支在标废或结案时随 Worktree 一并删除。

**以下四条约束适用于使用 `docs/TASKS.md` 队列时（拓扑 B 必选，拓扑 A 建板时同样遵守）**：

- **状态值**：`pending | verified | blocked | superseded`，只存在于里程碑上，切片没有独立状态。`pending` 同时表示排队中和执行中，没有“进行中”状态。
- **前置（`Depends-On`）**：里程碑之间的先后写在 `Depends-On` 字段里，不另设排队状态。前置全部 `verified` 后才可派发；前置被标 `superseded (by #M)` 时沿链追踪至最终替代里程碑；前置被标 `blocked` 时，依赖它的里程碑保持 `pending`、不派发，等 Brain 处理。
- **Brain 只追加或标废**：新里程碑追加在末尾，不覆盖或删除仍为 `pending` 的区块；要改一个未完成（含 `pending` 与 `blocked`）的里程碑，一律把它改为 `superseded (by #M)` 并追加新里程碑，不做原地局部改写；若直接取消且无替代，标为 `superseded (cancelled)` 并同步处理依赖它的下游里程碑，不把 `blocked` 静默改为 `verified` 以免依赖它的 `pending` 单收不到唤醒。Brain 派单或标废时只提交 `docs/TASKS.md`（`git commit --only docs/TASKS.md`）；更新其他契约或台账文档时同样用 `--only` 显式列出目标文件并及时提交，不把后台 Worker 尚未提交的代码带进提交。
- **滑动窗口与两级分诊**：文件里只保留未结案区块（`pending`、`blocked`）和最近 1~2 个已结案区块（`verified`、`superseded`）作锚点，更早的在追加新单时移出，历史交给 `git log`；凡仍被未结案里程碑的 `Depends-On` 直接或经 `superseded` 链引用的区块，不得移出滑窗。面对大量外部 Issue 或 PR 时，先在仓外去重、聚类、筛掉噪音，只把近期确认要做的事组织成里程碑放上调度板。

## 执行循环（主控 / Router）

调度者只派生、不亲自改切片代码。拓扑 A 由主会话在当前窗口直接驱动以下循环（跳过 `TASKS.md` 队列提交与 `post-commit` 唤醒）；拓扑 B 由无人值守 Router 在被唤醒后严格按全流程执行：

1. **取单与崩溃幂等恢复（拓扑 B）**：每次取单前重读项目的角色契约（`docs/ROLES.md`）与 `docs/TASKS.md`，协议改动因此在下一个里程碑生效，不依赖重新唤醒。按序取第一个前置已满足的 `pending` 里程碑，先检查 `main` 历史（`git log --grep="Milestone: #<N>"`）——若该里程碑的代码已在崩溃前线性合入 `main` 但尚未核销 `verified`，跳过重做并直接补齐结案提交；否则开始派发。取单时不改状态、不提交。
2. **派切片**：拓扑 B 每次派发前重读 `docs/TASKS.md`；若该里程碑已被标为 `superseded`，立即停止派发，关闭该里程碑已派生的 Worker 与 Tester，清理对应 Worktree 与未合入草稿分支，转去下一个 `pending`。完整里程碑/切片在本地短命分支或隔离 Worktree（`.tmp/worktrees/` 或宿主原生隔离工作树）中开发与返工（不把 `wip:` 半成品推上远端或直接落入 `main`）；Scope 正交的切片可并行（见下文“并发、Worktree 与主干线性收口”），有跨目录接口依赖的按序派。
3. **切片实现**：派 Worker 在分配的短命分支或隔离 Worktree 内实现并提交业务代码，Worker 交卷前必须跑通工程门禁（见下文“验证分工”）。
4. **整合候选树与验收**：写文件正交不等于组合正确（`T(A) ∧ T(B) ⇏ T(A ∪ B)`）。多切片里程碑在全部切片交卷后，**必须先在临时集成候选分支/工作树合出包含全部切片的唯一整合树（`A ∪ B ...`）并跑通一次全仓门禁**；里程碑改变了外部可观测表面（GUI、CLI、API 行为）时，派一个全新的 Tester 针对该整合候选树做一轮验收；验收栏写“无”（内部重构、测试、文档、工具）则跳过 Tester，靠整合候选树门禁证据与 Auditor 兜底。
5. **打回时现场处理（显性问题不出执行环）**：
   - 实现漏项、交互或排版瑕疵、测试逃逸，以及完成里程碑目标所需、但切片漏列的同切面支撑文件（只要不在“不在范围内”或禁区里），一律由调度者当场拍板：直接授权补改、指明根因方向，按报告里的文件位置归因到切片，让对应 Worker 返工、同一 Tester 复验（拓扑 B 不转给 Brain）；
   - 每次打回，对比 Worker 自检报告与 Tester 的发现，先判定缺陷背后的**机制**，即哪个隐含的模型或假设失效，同时核对 `docs/LESSONS.md` 正文与文末的已晋升列表，再把“为什么没在自检中被拦下”记入 `docs/LESSONS.md`（新增或累加 `Seen N×`）。`Seen N×` 按机制计，同一机制的不同症状合并为一条，不按症状或打回次数计；
   - 同一机制在同一里程碑内第二次出现（症状可以不同），或已晋升为守卫的机制再次出现，停止派表层补丁，改派**机制级修复**：Worker 先把隐含模型写成显式、确定的实现，再补覆盖该机制输入维度的矩阵测试（若命中已晋升机制，则直接扩充原守卫测试的输入维度，不另建重复的 `Seen 1×` 条目），并把矩阵交给同一 Tester 在复验中全量覆盖；
   - 某条规则累计 `Seen 3×` 或属严重回归：能写成测试的，令 Worker 在返工时固化为 `tests/` 下的守卫测试，守卫必须覆盖该机制的输入维度，不能只锁住见过的例子；需要改项目契约文档或 Skill 才能落实的，升级交 Brain 与人裁定（拓扑 B 标 `blocked`）。晋升后把该条从 `docs/LESSONS.md` 正文移到文末的已晋升列表，保留机制名与指向守卫测试或正式文档的记录。
6. **升级（`blocked`）**：只在以下情况停止返工并升级（拓扑 B 把证据写回该里程碑区块、状态改为 `blocked` 并只提交 `docs/TASKS.md`，随后关闭该里程碑的 Worker 与 Tester 并清理不再使用的 Worktree 与分支；拓扑 A 直接向人汇报证据请人裁定）：需要改动上游已冻结的公共契约或契约本身自相矛盾；需要触碰里程碑“不在范围内”或禁区里的文件；需求有业务价值上的二义性需要人取舍；涉及破坏性操作；同一里程碑连续 3 轮返工仍未通过验收。
7. **线性收口与结案**：整合候选树验收（及合并前按需审计）通过后，使用 `docs/TASKS.md` 时**先重读确认该里程碑未被标为 `superseded`**（若已标废则严禁合入 `main`，立即关闭成员并清理 Worktree 与未合入草稿分支，转去下一个 `pending`）；确认有效后，按「最小可独立回滚语义单元」（单切片或强耦合不可独立回滚的多切片 = 1 条；可各自独立通过编译测试与回滚的正交切片 = 每切片 1 条）将变更 **Squash 线性合入 `main`**（严禁 `wip:` 与菱形 `merge commit` 落入 `main`），确认落盘后的 `main` 树与已验收候选树内容一致（`git diff <candidate-tree> HEAD` 为空），并在 Commit Body 写明 `Milestone: #<N>`（供崩溃重启幂等核销）与完整验证证据；确认合入 `main` 后立即关闭该里程碑的 Worker 与 Tester、删除对应本地分支与 Worktree；项目有功能台账时按「功能台账」一节同步 `docs/FEATURES.md`。拓扑 B 随后只改该区块状态为 `verified` 并填 `Verified-Commit`（最终线性落入 `main` 的业务提交 SHA），只提交 `docs/TASKS.md`（有台账时一并提交 `docs/FEATURES.md`）。
8. **排空（拓扑 B）**：每次提交后、结束回合前重读 `docs/TASKS.md`。只要还有前置已满足的 `pending` 里程碑（包括执行期间 Brain 新追加、但没有单独唤醒你的里程碑），就在当前回合继续执行，不等新的唤醒；只剩前置未满足的 `pending` 时进入睡前审计或休眠。
9. **审计（Auditor，双节点 + 实证门槛 + 核实闭环）**：
   - **触发条件**：① 重大架构、Schema 或复杂机制定稿前，由 Brain 主动派生 Auditor 做只读红队反证；② 合并前、发版前，或拓扑 B 队列排空后满足任一条件——自 `docs/LESSONS.md` 首行 `reviewed-through` 起已结案不少于 2 个里程碑（初始值，项目可在 `docs/ROLES.md` 调整），或其间有里程碑跳过了 Tester（若 `docs/LESSONS.md` 尚未建立，则自首个里程碑提交起算并在本轮审计后创建该文件）。
   - **模型与沙盒**：派生一个全新的只读冷会话，**优先使用与当前主力异源的主流旗舰推理模型 + 高推理深度**（具体型号与深度由 Brain/项目环境决定，不硬编码；参考实现见 [references/cross-model-audit.md](references/cross-model-audit.md)）。
   - **实证门槛**：Auditor 只报告有明确依据的四类实证，无实证输出 `NO_ISSUES`，严禁主观风格建议：
     - **改坏不红**：注释或改反被测核心代码后，测试仍然通过（或指出具体逃逸分支）；
     - **反模式行号**：指出 `文件:行号` 处违反明文禁止的写法（同名包装、事件截胡、固定延时等待就绪、读源码字符串假测试、Fail-open 静默跳过等）；
     - **契约背叛**：指出代码、方案或里程碑区块违背 `AGENTS.md`、`ARCHITECTURE.md`、`PRODUCT.md` 的具体条目；
     - **真实缺陷与边界漏洞**：指出 `文件:行号` 与可复现触发路径（逻辑错、状态机漏分支、并发竞态等）。
   - **核实与清创**：调度者拿到审计报告后**必须逐条读源码/复现核实，不盲从**；区分真问题与误报后，仅对经核实的实证问题当场派生新的 Worker 清理，并按第 4 步规则决定是否派 Tester 复验。若维护 `docs/LESSONS.md` 水位线，全部干净后把首行 `reviewed-through` 更新为最新 `HEAD` 并单独提交（只含 `docs/LESSONS.md`）；拓扑 B 提交后再重读一次 `docs/TASKS.md`，确认审计期间没有新进且前置已满足的 `pending` 里程碑后才休眠。

拓扑 B 下“只提交 `docs/TASKS.md`”约束的是派单、升级与结案这类调度提交；`docs/LESSONS.md` 的记账与水位线提交单独进行，同样不夹带业务代码。结案时同步的 `docs/FEATURES.md` 是例外，它记的正是这次结案的结论。

## 验证分工

- **Worker 每个切片的交卷前置条件**：编译、类型与静态检查、全仓单元测试与守卫测试、构建打包全部跑通（不只跑改动所在的包）；对新增或修改的关键测试做手动破坏验证（故意改坏被测逻辑，确认测试变红，再改回）；业务提交的正文写明意图或根因与验证证据；涉及 UI 的改动，自己对真实渲染结果截 1~3 张图存入 `.tmp/evidence/milestone-<N>/`，并用图像查看工具亲自看一遍，当场修掉明显的重叠、截断、错位。门禁与验收的默认值写在项目的 `docs/ROLES.md`（或根 `AGENTS.md`），里程碑里只写偏离默认的项。
- **Tester 只做一件事：模拟真实用户**。怎么验由产品形态决定：CLI 按用户手册敲命令看输出，API 发真实请求看状态流转，GUI 与网页在专用沙盒里像普通用户一样操作（在具备原生浏览器代理的宿主中优先使用原生浏览器代理）并逐屏截图检查排版、位置与文案。每个里程碑一轮验收，把整条用户路径上的问题一次列全，不分轮挤牙膏；里程碑写了验收矩阵时，第一轮按矩阵全量覆盖。通过验收的截图保留在 `.tmp/evidence/milestone-<N>/`，这就是人做最终审美裁定的节点。

## 功能台账（可选）

项目建了 `docs/FEATURES.md`（何时建立与格式见 `project-governance` Skill）时，里程碑与台账按下面四条联动。跳过 Tester 的里程碑靠它记下验收债，不让旧验收悄悄过期。

1. **列条目（共享内核改动保守扩大）**：Brain 在里程碑的 `Features` 字段列出它推进或动到的条目，没有写“—”；**凡改动共享内核、持久化/存储格式、权限或公共协议的里程碑，必须保守将受影响子系统的全部已验收条目一并列入 `Features`**（宁可多复验，不靠盲猜遗漏间接波及）；条目增删归 Brain，改完 `docs/FEATURES.md` 须立即独立提交，不留未提交草稿在工作区与结案提交撞车。
2. **逐行结论**：Tester 的验收报告按这些条目逐行写结论与未覆盖的部分。
3. **结案同步**：调度者在结案前重读 `docs/FEATURES.md`，只改该里程碑 `Features` 所列条目对应的行：① **功能清单**：独立验收通过的改为 `已验收`，更新覆盖列（`✓ / ○ / –`）、`最近独立验收`（`#<里程碑> @<Verified-Commit>（日期）`，使用受控夹具时标「受控」）与`已知缺口`；动到但没有独立验收的降为 `待复验`（验收栏写“无”、跳过 Tester 的里程碑照此处理）；② **回归测试表**：为本里程碑新实现或变更测试的条目补齐/更新测试文件链接；③ **发布与版本**：若为发布里程碑，同步更新当前发布版本与对应行的发布状态为 `已发布`。提交前跑通台账守卫测试（拓扑 B 与 `docs/TASKS.md` 同一次提交：`git commit --only docs/TASKS.md docs/FEATURES.md`）。
4. **发布前清债**：写明发布版本的里程碑，先把这个版本范围内的 `待复验` 条目按真实用户路径重新独立验收，再发布；自动化测试是绿的不能代替这一步。

## 并发、Worktree 与主干线性收口

| 工作类型 | 并发上限 | 前提 |
| --- | --- | --- |
| 局部微调或上游契约冻结 | 0（主控直接做） | 不超过 5 步工具调用；可直接单次干净提交到 `main`；涉及完整业务切面或耗时测试的，交给 Worker |
| 单切片里程碑写入 | 1 | 同一工作树同一时刻最多 1 个写代码的 Worker；在本地短命分支或隔离 Worktree（拓扑 B 优先独立 Worktree 以免占用 `main` 主工作树）中开发与返工 |
| Worktree 并行写 | 2~3 | 同一里程碑内 `Scope` 正交的切片且上游共享 Schema 已冻结；或下一个里程碑与当前里程碑的 `Scope` 完全正交（流水线重叠，默认关闭，因为会建立在尚未验收的代码之上） |
| 只读探索、分诊、审查 | 2~4 | 按正交子系统或审查维度扇出，不按零碎文件拆分 |

隔离工作树与主干线性收口遵循五点约束（拓扑 A 中若宿主原生提供隔离工作树机制如共享工作树/分支工作区，优先直接使用宿主原生机制并在确认合入后清理；手动管理或拓扑 B 时由 Router 独占管理；通用 PR Rebase、Merge Queue 与公开仓隐私邮箱细则以 `engineering-discipline` Skill 为准）：

1. **草稿隔离，线性收口**：完整里程碑/切片在本地短命分支或隔离 Worktree 中开发与多轮返工；`main` 只接收验收与按需审计通过后的线性原子提交，严禁 `wip:` 半成品与菱形 `merge commit` 落入 `main`。按「最小可独立回滚语义单元」（单切片里程碑 = 1 条；多正交切片 = 每切片 1 条）Squash 线性合入 `main` 并把完整验证证据写入 Commit Body；绝不改写或强推已落入 `main` 的历史。
2. **开在哪**：手动管理时统一建在本仓库内已加入 `.gitignore` 的 `.tmp/worktrees/m<N>-s<K>`，不用全局共享临时目录或仓库外的父目录。放在未被忽略的目录时，主工作树的一次 `git add -A` 会把它当作嵌套仓库暂存进提交。
3. **不推远端、用完即清**：本地多 Agent 探索与切片分支不推送远端；确认已线性合入 `main`（或所在里程碑被标为 `superseded`）后，立即删除对应 Worktree 与本地分支，不残留废弃工作树或僵尸分支。
4. **冲突重放优于硬解**：分支落后过久或与新冻结契约硬冲突时，放弃旧分支，基于最新 `main` 重放意图与守卫测试，不硬解腐烂文本冲突。
5. **公开仓库隐私检查**：跨仓或开源仓合入前确保提交身份使用平台 noreply 隐私邮箱，不暴露个人真实邮箱。

## 上下文管理

- **Inline & Spill**：Brain 与 Router 只在对话里保留里程碑 ID、结论摘要和文件路径，完整细节、Diff 审计日志与证据写到工作区文件里按需读取。

## 通信契约

角色之间通过下面两种结构化文本交接（拓扑 A 中可直接作为子代理 Brief 与回报结构，拓扑 B 中落盘于 `docs/TASKS.md` 与报告文件），不靠口头的模糊指令。

### 里程碑区块（Brain 写入 `docs/TASKS.md` 或任务 Brief）

```markdown
## [Milestone #<N>] <用户能做到什么>
- **Status**: pending
- **Verified-Commit**: none
- **Depends-On**: —（有前置时写编号，如 `#12, #13`）
- **Features**: —（项目有功能台账时，列出推进或动到的条目 ID）
- **用户可观测目标**：这个里程碑完成后，用户能端到端做到什么
- **Tester 验收**：一条真实用户操作路径、要检查的视觉与交互点、期望结果，一轮跑完；涉及渲染、版式、并发等组合空间大的机制时，同时写明验收矩阵的维度；没有外部可观测变化时写“无”
- **不在范围内**：明确排除的功能，以及不可触碰的目录（上游冻结契约、用户真实数据等）

### 切片
1. **S1** `Scope: <允许修改的文件或目录前缀>`：行为契约（输入、输出、边界条件、错误处理、性能要求）；完成本切片所需的同切面支撑文件，调度者可直接授权补改
2. **S2** `Scope: <前缀>`：行为契约；Scope 与 S1 正交才单独成片
3. **S3**（依赖 S1）`Scope: <与 S1 正交的前缀>`：行为契约；仅当 Scope 正交但存在跨目录上下游接口先后时单列并按序派发，Scope 重叠或同切面串行逻辑并入同一切片
```

工程门禁与验收方式的默认值写在项目的 `docs/ROLES.md`（或根 `AGENTS.md`），区块里只写偏离默认的项，更新时间由 Git 记录。只有一个切片时，`Scope` 直接写在区块里，省掉切片小节。

### 验收报告（Tester → 主控 / Router）

```markdown
# 验收报告：[Milestone #<N>] <里程碑名称>
- **结论**：通过 | 实现或体验问题（退回 Worker） | 核心契约冲突（升级裁定 / 标记 blocked）
- **边界核对**：是否触碰未授权的契约；Worker 的全仓门禁与破坏验证是否齐备
- **真实用户验收证据**：实际操作过程、截图检查结论或真实输出记录
- **台账逐行结论**：里程碑列了 `Features` 时，按条目写通过、未通过与未覆盖的部分
- **必须修复项**：现象、违背的用户预期或契约条目、复现路径、对应文件位置
- **需升级裁定项**：契约冲突点或架构缺陷说明
```

## 参考实现与唤醒机制

- **跨模型异源协作与交叉审计**：全周期五大异源模式（方案互搏、疑难破盲、对抗测试、第一性体检、diff 实证审计与显式隔离写双向互审）、活性心跳监控、零硬编码模型优先级与主流 CLI 范式见 [references/cross-model-audit.md](references/cross-model-audit.md)。
- **跨窗口双环唤醒（拓扑 B）**：默认参考实现是 Git 总线——Brain 提交 `docs/TASKS.md` 新增的 `pending` 里程碑，`post-commit` 钩子按 diff 边沿触发唤醒该项目专属的常驻 Router；Router 自己的结案提交不新增 `pending` 行，不会自激。钩子模板、唤醒消息与审计计数命令见 [references/git-bus.md](references/git-bus.md)。

## 升级链与人的介入

升级链固定为：`Worker ↔ Tester ↔ 调度者（Router） → Brain → 人`（拓扑 A 中主会话兼任 Brain 与 Router，直接对人升级）。

- **不出执行环**：显性实现或体验缺陷、切片漏列的同切面支撑文件，由调度者现场裁决（见执行循环第 5 步）。
- **升级至 Brain / 人**：执行循环第 6 步列出的情况；以及需要改变项目对外目标或范围、多个技术方案之间存在业务价值取舍时唤醒人裁定。

## 验收清单

- [ ] 拓扑匹配宿主能力：单宿主原生编排不硬套外部 Git 总线，跨窗口无人值守双环显式立住 Router 并配齐 `ROLES.md` 与钩子
- [ ] 角色边界清晰：调度者只派生不代做、按机制分诊并记 `docs/LESSONS.md`，Worker 实现切片并跑通全仓门禁与破坏验证，Tester 按里程碑独立模拟真实用户验收
- [ ] 使用 `docs/TASKS.md` 队列时采用独立里程碑区块与切片 `Scope`；Brain 与 Router 均用 `--only` 提交目标文件；Router 每次派切片前重读该文件，精确结案并在睡前排空全部可执行 `pending`
- [ ] Worker、Tester、Auditor 均按需派生、用完即关，Tester 每个里程碑都是全新会话
- [ ] 里程碑之间的先后只写在 `Depends-On` 里，没有另设排队状态；拓扑 B 的 Router 每次取单前重读 `docs/ROLES.md`
- [ ] 有功能台账时，结案同步了里程碑所列的行，跳过 Tester 而动到的条目已降为 `待复验`
- [ ] Auditor 优先选用与主力异源的旗舰高推理模型（不硬编码型号），只凭实证报告，且主控逐条核实后再派清理
- [ ] 同一工作树没有多个 Agent 同时写；完整里程碑/切片在本地短命分支或隔离 Worktree（手动管理置于 `.gitignore` 的 `.tmp/worktrees/`）中开发与返工，验收通过后按最小语义单元 Squash 线性合入 `main`（无 `wip:` 与菱形 `merge commit`、不改写 `main` 已有历史、本地分支不推远端），合入或标废后立即清理 Worktree 与分支
- [ ] Tester 的放行依据是符合产品形态的真实用户操作与观测证据，而不是重跑测试脚本
- [ ] 角色定义不依赖特定宿主、模型型号或调试框架
